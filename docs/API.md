API библиотек HMAC и JWT
=========================

Документ описывает все экспортируемые процедуры и функции модулей `Криптография.bsl` и `JWT.bsl`, входящих в проект.  
Каждая запись содержит назначение, параметры, возвращаемые значения, особенности и пример использования.  
Во всех примерах предполагается, что модули подключены в конфигурацию и доступны по их именам.

Общие требования
----------------

- Платформа: 1С:Предприятие 8.3.10.2168 и выше.
- Алгоритм JWT: поддерживается только HS256.
- Алгоритмы HMAC: MD5, SHA1, SHA256 (ограничения реализованы в коде).

Модуль `Криптография`
---------------------

### `ХАКС(СекретныйКлюч, Сообщение, ХешФункц)` **(Экспорт)**

**Назначение.** Вычисляет HMAC (RFC 2104) для произвольных двоичных данных.

**Параметры.**
- `СекретныйКлюч` (`ДвоичныеДанные`) — ключ для подписи. Если длина превышает 64 байта, ключ предварительно хешируется.
- `Сообщение` (`ДвоичныеДанные`) — данные, для которых требуется MAC.
- `ХешФункц` (`ХешФункция`) — значение перечисления `ХешФункция.MD5 | SHA1 | SHA256`.

**Возвращает.** `ДвоичныеДанные` — вычисленный MAC.

**Особенности.**
- Перед вычислением выполняется проверка поддерживаемости алгоритма (см. `ПроверкаПоддержкиХешФункции`).
- Поддерживается только блочный размер 64 байта (HMAC для SHA2-256).
- Для сравнения результата с внешними системами используйте `Base64Строка()` или `СтрокаВШестнадцатеричномПредставлении()`.

**Пример.**

```bsl
Секрет = ПолучитьДвоичныеДанныеИзСтроки("Ключ");
Сообщение = ПолучитьДвоичныеДанныеИзСтроки("payload");
Подпись = Криптография.ХАКС(Секрет, Сообщение, ХешФункция.SHA256);
```

### `Хеш(Значение, ХешФункц)` **(Экспорт)**

**Назначение.** Быстрое вычисление хеша для переданных двоичных данных.

**Параметры.**
- `Значение` (`ДвоичныеДанные`) — данные, которые нужно хешировать.
- `ХешФункц` (`ХешФункция`) — алгоритм хеширования (совпадает с перечислением платформы).

**Возвращает.** `ДвоичныеДанные` — результат работы `ХешированиеДанных`.

**Особенности.**
- Используется внутри `ХАКС`, но может применяться отдельно, если требуется получить MD5/SHA1/SHA256 без HMAC.
- Для строковых входных данных их нужно преобразовать в `ДвоичныеДанные`.

**Пример.**

```bsl
Данные = ПолучитьДвоичныеДанныеИзСтроки("plain text");
Отпечаток = Криптография.Хеш(Данные, ХешФункция.SHA1);
```

Модуль `JWT`
-----------

### `Зашифровать(СекретныйКлюч, ПолезнаяНагрузка = Неопределено, ДопЗаголовки = Неопределено)` **(Экспорт)**

**Назначение.** Формирует JWT-токен с симметричной подписью HS256.

**Параметры.**
- `СекретныйКлюч` (`Строка`) — секрет для расчёта подписи (рекомендуется длина ≥ 32 байт).
- `ПолезнаяНагрузка` (`Структура`) — данные, попадающие в тело токена. Если не задано, создаётся пустая структура.
- `ДопЗаголовки` (`Структура` | массив структур) — пользовательские заголовки `header`. Ключи и значения добавляются поверх `typ` и `alg`.

**Возвращает.** `Строка` — готовый JWT в формате `header.payload.signature`.

**Особенности.**
- Заголовок формируется автоматически (`typ=JWT`, `alg=HS256`).
- Подпись вычисляется через `Криптография.ХАКС` и кодируется в Base64Url.
- Для сложных структур полезной нагрузки полагайтесь на внутренний JSON-сериализатор `СформироватьJSON`.

**Пример.**

```bsl
ПолезнаяНагрузка = Новый Структура;
ПолезнаяНагрузка.Вставить("sub", "1234567890");
ПолезнаяНагрузка.Вставить("exp", ТекущаяДата() + 3600);

Токен = JWT.Зашифровать("СуперСекрет", ПолезнаяНагрузка);
```

### `Расшифровать(Токен, СекретныйКлюч, Проверка = Истина)` **(Экспорт)**

**Назначение.** Декодирует JWT и, при необходимости, проверяет подпись.

**Параметры.**
- `Токен` (`Строка`) — входной JWT.
- `СекретныйКлюч` (`Строка`) — секрет, которым токен был подписан.
- `Проверка` (`Булево`) — выполнять ли верификацию подписи и соответствия алгоритма.

**Возвращает.** `Структура` — полезная нагрузка токена.

**Особенности.**
- Проверка алгоритма обязательна при `Проверка = Истина`; при несоответствии выбрасывается исключение.
- Подпись сверяется по Base64-представлению HMAC.
- Для кастомных проверок (срок действия, `aud`, `iss`) нужно анализировать возвращённую структуру отдельно.

**Пример.**

```bsl
ПолезнаяНагрузка = JWT.Расшифровать(Токен, "СуперСекрет");
Если ПолезнаяНагрузка.exp < ТекущаяДата() Тогда
	ВызватьИсключение "Токен истёк";
КонецЕсли;
```

### `СформироватьJSON(Объект, ПереносСтрок = Неопределено)` **(Экспорт)**

**Назначение.** Утилита сериализации структур, соответствующая внутренней логике JWT-модуля.

**Параметры.**
- `Объект` — любой сериализуемый объект платформы (структура, массив, соответствующие типы).
- `ПереносСтрок` (`ПереносСтрокJSON`) — режим форматирования, по умолчанию `ПереносСтрокJSON.Нет`.

**Возвращает.** `Строка` — JSON-представление. Если объект пуст, возвращает пустую строку.

**Пример.**

```bsl
Данные = Новый Структура;
Данные.Вставить("name", "demo");
JSON = JWT.СформироватьJSON(Данные, ПереносСтрокJSON.Да);
```

### `РазобратьJSON(JSON)` **(Экспорт)**

**Назначение.** Преобразует строку в структуру/массив платформы 1С.

**Параметры.**
- `JSON` (`Строка`) — корректная JSON-строка.

**Возвращает.** Объект, соответствующий содержимому JSON; `Неопределено`, если вход пуст.

**Пример.**

```bsl
СтруктураДанных = JWT.РазобратьJSON("{""sub"":""123"",""role"":""admin""}");
```

### `Тест()` **(Экспорт)**

**Назначение.** Минимальный пример генерации и проверки токена, пригодный для быстрой проверки подключения модуля.

**Поведение.**
- Формирует payload с демонстрационными полями.
- Создаёт JWT и тут же декодирует его.
- Использовать как шаблон для smoke-теста после интеграции.

Дополнительные рекомендации
---------------------------

- Для хранения секретов используйте защищённые хранилища 1С и не фиксируйте их в коде.
- Для передачи токенов по сети применяйте HTTPS.
- При проверке JWT добавляйте бизнес-правила (время жизни, аудитории, список разрешённых клиентов).
- Если требуется поддержка других алгоритмов (RS256/ES256), придётся расширить модуль `JWT.bsl`.
